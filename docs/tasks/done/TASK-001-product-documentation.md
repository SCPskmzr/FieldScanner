# TASK-001 — Модульная документация реализованного продукта

## Goal

Сформировать единое актуальное описание FieldScanner по коду, разделённое на фичи и модули, и предотвратить его устаревание.

## Requirements

- Описать экраны, основные пользовательские потоки, руны, хранение, AI и телефонию.
- Указать ограничения, требующие проверки на устройстве.
- Добавить проверку соответствия изменений кода и документации в local verify и CI.

## Plan

Задокументировать реализованное состояние, не меняя логику приложения, и добавить предсказуемую проверку актуальности. Создать индекс `docs/README.md` и шесть модульных страниц. Сопоставить пути исходников с этими страницами в `scripts/check-documentation`, подключить их к существующим `verify` и CI. Агент обновляет содержательное summary по diff, а проверка требует совместного изменения кода модуля и его страницы.

Риск: `MainActivity` затрагивает несколько потоков — сопоставлен с UI-документом; при изменениях сканера, журнала или телефонии нужно обновлять также соответствующую фактическую страницу.

## Acceptance criteria

- [x] Есть единый индекс документации и отдельные страницы модулей.
- [x] Каждая страница привязана к зоне исходного кода.
- [x] `verify` требует обновления документации при изменении модуля.
- [x] Проверка документации и полный `verify` запущены.

## Outcome

Добавлены `docs/README.md` (индекс) и страницы `docs/modules/*.md`; `scripts/check-documentation` увязывает зоны кода со страницами и встроен в `verify` и CI. Реализовано в коммитах `9a21466`, `eea5d71`, `9f3a4ef`, `5d46cf8` (до внедрения схемы `TASK-NNN` в subject). Ограничений не осталось.
