# Находки и журнал

## Что сохраняется

После успешного анализа `FindingRepository` сохраняет фото во внутреннем `files/findings/`, запись в Room и доступную геолокацию. Запись содержит идентификатор, URI фото, заголовок, описание, confidence, `visualId`, URI аудио, координаты/точность и время создания. Аудиофайл добавляется отдельным шагом после синтеза. Снимок можно также сохранить без анализа: он получает нейтральные заголовок и описание, `visualId = UNKNOWN_OBJECT`, без аудио и геолокации.

`visualId` хранит валидированное значение из плоского каталога `ScanVisual` (`ScanOutlineCatalog.kt`, 100 архетипов) и сохраняет визуальную идентичность находки между перезапусками. Старые записи и снимки без анализа используют `UNKNOWN_OBJECT` — терминальный фолбэк, который детерминированно приводит к процедурному фолбэку контура.

## Журнал

Пользователь открывает журнал из неактивного сканера. ViewModel загружает находки, показывает одну запись, позволяет переключать её, воспроизводить сохранённый MP3 и фильтровать по результату встроенного Android speech recognizer. Текущую запись можно удалить только после подтверждения; удаляются и запись Room, и её внутренние медиафайлы. Первая команда Flux открывает безтекстовое подтверждение: нижний сегмент показывает символ корзины, а доступны только Ember (зелёное подтверждение) и Drift (синяя отмена). Ember удаляет текущую запись через существующий `FindingStore.deleteFinding`; Drift возвращает к ней без изменений. После успешного удаления журнал выбирает следующую доступную запись либо возвращает неактивную камеру, если записей не осталось.

## Код и ограничения

- `JournalCoordinator` изолирует загрузку, навигацию и фильтрацию журнала от `MainActivity`; `AudioPlaybackController` управляет единственным активным narration player, а `VoiceSearchController` — короткой сессией Android speech recognizer.

- Контракты: `FindingStore`, `Finding`, `AnalysisResult`, `ScanVisual` (`ScanOutlineCatalog.kt`).
- Persistence: `FindingsDatabase`, `FindingDao`, `FindingEntity`, `FindingRepository`.
- Медиа записывается атомарным копированием через `FindingMediaStorage`.
- Геолокация вынесена в общий пакет `com.fieldscanner.app.data.location` (`DeviceLocationProvider` / `FindingLocation`), потому что ею пользуется и левый дисплей; она использует `LocationManager`, доступные provider и последний свежий результат, необязательна и может отсутствовать. `FindingRepository` обращается к ней через импорт из `data.location`, а не как к соседнему классу пакета.
- Миграции Room необходимо добавлять при изменении схемы; база содержит migration 1→2 (audioUri) и 2→3 (`visualId TEXT NOT NULL DEFAULT 'UNKNOWN_OBJECT'`), текущая версия схемы — 3.
- При ошибке сохранения фото, находки, аудио или удаления `FindingRepository` записывает исходное исключение через `DiagnosticsLog` и затем выполняет прежнюю очистку/передачу ошибки вызывающему слою.
